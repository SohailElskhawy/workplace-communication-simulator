Research → design decisions

Less interface to think about.

A proposal for review, based on the current source code and published usability guidance. These are design hypotheses, not results from testing Kalemny users.

There isn’t one “most comfortable” font.

Reading research finds meaningful individual differences. It does not establish one typeface as best for everyone, and preference is not the same as reading performance. Read NN/g’s research summary.

Recommendation: use the familiar system sans-serif consistently for headings, controls, and conversation text. Use 16–17px body text, 14px supporting text, 1.6 line height, and restrained weights. Compare font directions with the selector above; this is a prototype control, not a proposed user setting.

Does speaking take too many steps?

Default tap flow: three actions. Start → Stop → Send. Speech, transcription waiting, and optional editing sit between those actions. First-use browser permission is one additional setup action.

Auto-send: two actions. Start → Stop, then transcription and send happen automatically. The current implementation already offers this. The proposed design preserves the explicit choice.

The main improvement is predictability. Review stays optional, controls stay in place, the latest conversation stays visible, and pauses don’t trigger an unexpected transition. Hold Space is an optional shortcut, not a required gesture.

Comfort comes from the whole system

Visible status, familiar controls, user control, and recognition rather than recall support the stable composer and explicit action labels. These are applications of NN/g’s usability heuristics, not proof of a preferred visual style.

Use a 44px product target for controls, exceeding WCAG 2.2 AA’s 24px minimum with its spacing exceptions. Aim for at least 4.5:1 contrast for ordinary text, visible focus, and complete readable error messages.

Validate before implementing broadly

Run a small formative study with 5–8 students and early-career professionals on desktop and mobile. Ask each to start a session, pause mid-answer, correct a transcript, interrupt playback, recover from a microphone error, and find their next coaching action.

Compare task completion, accidental sends, premature stops, time to send, correction effort, and self-reported comfort. Counterbalance design order. A small study finds problems; it cannot establish what most people prefer.

Scope: this is a standalone prototype. The approved app design, real voice engine, API, and database have not been changed by this proposal.
